# パスワード強度表示 仕様

## 目的

生成結果ごとに、単一の `Very Strong` などの大まかな表現ではなく、複数の観点から根拠が分かる強度評価を表示する。

短いランダム文字列が `Very Strong` に見えてしまう状態を避け、ユーザーが「何が強く、何が弱いのか」を判断できる表示にする。

## 参考情報の採用判断

このアプリは「ユーザーが入力したパスワードを検査するサービス」ではなく、「暗号学的に安全な乱数でパスワードを生成するローカルアプリ」である。そのため、参照情報は無条件に取り込まず、生成アプリの評価に必要な範囲だけ採用する。

### 主軸として採用する

- NIST SP 800-63B
  - 単一要素の password は 15 文字以上を要求する。
  - MFA と組み合わせる場合でも 8 文字未満は弱い。
  - 最大長は少なくとも 64 文字を許容する。
  - 大文字・小文字・数字・記号の混在を必須にするような composition rule は課さない。
  - 既知の漏洩パスワード、よく使われるパスワード、期待される単語との blocklist 照合を重視する。
  - 採用理由: 長さ、文字種強制を避ける方針、blocklist の扱いが評価仕様の基礎になる。
- OWASP Authentication Cheat Sheet
  - MFA なしでは 15 文字未満、MFA ありでも 8 文字未満を弱いものとして扱う。
  - パスワード強度メーターの利用を推奨する。
  - 過去に漏洩したパスワードや一般的な弱いパスワードのブロックを推奨する。
  - 採用理由: アプリの強度メーター表示、補助メッセージ、弱い候補の扱いに直結する。

### 補助参考として採用する

- NCSC UK
  - `three random words`、パスワードマネージャー、2-step verification、passkeys など、利用者に伝わりやすい説明が実用的。
  - 採用範囲: ヘルプ tips の言い回し、長さと推測されにくさを重視する説明。
  - 採用しない範囲: このアプリは現時点でランダム文字列ジェネレータなので、3単語パスフレーズ生成の基準は現在の評価軸には入れない。
- Dropbox zxcvbn
  - 辞書語、名前、日付、繰り返し、シーケンス、キーボード配列、leet 変換を見て推測コストを見積もる考え方が有用。
  - 採用範囲: `既知リスク` と `推測されにくさ` の検出カテゴリ。
  - 採用しない範囲: 本家 zxcvbn の辞書データ、guess count、crack time、スコア互換性までは実装しない。
- RFC 4086
  - 秘密値生成には十分なランダム性と探索空間が必要という考え方が、パスワード生成アプリに直接関係する。
  - 採用範囲: 暗号学的に安全な乱数、entropy bits、総当たり耐性の説明。

### 現時点では採用しない

- Have I Been Pwned Pwned Passwords のオンライン照合
  - 採用しない理由: このアプリはローカル完結を基本とし、生成結果を外部へ送らない。k-anonymity 方式でも外部通信が発生し、ユーザーの期待するオフライン性と異なる。
  - 代替: アプリ内の軽量 blocklist とパターン検出だけを使う。
- Have I Been Pwned などの全漏洩パスワードコーパス同梱
  - 採用しない理由: データサイズ、更新運用、ライセンス/配布、アプリ容量への影響が大きい。暗号学的にランダム生成した十分な長さのパスワードが既知漏洩リストに一致する可能性は極めて低く、生成アプリの標準機能としては費用対効果が低い。
  - 将来検討: ユーザーが明示的に有効化する任意のオフライン辞書パックや、手動の漏洩チェック機能は別仕様として検討する。
- CISA、Microsoft、CIS Controls、ISO 27001、PCI DSS などの組織運用向け資料
  - 採用しない理由: パスワード運用、MFA、期限、認証基盤、組織統制の比重が大きく、生成結果 1 件ごとの強度評価基準としては NIST/OWASP と重複する内容が多い。
- 機械学習型の password strength meter や大規模研究実装
  - 採用しない理由: モデル配布、透明性、ローカル処理、学習データの扱い、実装コストがこのアプリの範囲を超える。

## 対象画面

- メイン画面右カラム
  - 生成結果一覧
  - 各生成結果の総合評価
  - 主要評価軸のグレード
  - 生成バッチ単位の推定エントロピー、生成条件、ハッシュの補助情報
  - 既知リスクや推測されやすいパターンの警告

## 評価表示

### ヘルプ表示

- 右カラム上部の `生成結果` と進捗表示の近くに `?` アイコンボタンを置く。
- `?` アイコンボタンをクリックすると、強度評価の説明 tips をポップオーバーで表示する。
- tips には以下を簡潔に表示する。
  - `総合`、`長さ`、`総当たり耐性`、`推定エントロピー`、`条件`、警告メッセージが何を意味するか。
  - `推定エントロピー`、`条件`、`ハッシュ` は同じ生成結果セットでは共通のため、パスワード行ごとではなく生成結果一覧の上側に 1 回だけ表示すること。
  - `既知リスク` と `推測されやすいパターン` は加点評価ではなく、問題がある場合だけ総合評価を下げる警告であること。
  - `S` から `F` のグレードが、ユーザーにとってどの程度見直しが必要かを表すこと。
  - 15 文字以上を重視し、文字種の混在は必須条件として扱わないこと。
  - `推定エントロピー` は固定文字を除いた生成部分の探索空間から bits 単位で見積もること。
  - 漏洩データベースへのオンライン照合は行わず、アプリ内の軽量 blocklist とパターン検出による目安であること。
- tips の文章は、専門知識がないユーザーでも意味を追える表現を優先する。`推定エントロピー` のような必要な用語は残してよいが、用語だけで説明を終えない。
- tips は `表示ラベル` と `主な基準` のように同じ項目を別々の表で重複説明しない。ユーザーが上から読めば、画面上の表示と評価の意味を一続きで理解できる構成にする。
- tips はユーザーの確認補助であり、通常の生成操作を妨げない。

### 総合評価

- `Basic`、`Good`、`Strong`、`Very Strong` の表示は廃止する。
- 代わりに `総合評価` として `S`、`A`、`B`、`C`、`D`、`F` の 6 段階を表示する。
- 総合評価は、`長さ` と `総当たり耐性` を主軸に決める。
- `既知リスク` と `推測されやすいパターン` は、良い状態を加点するためには使わない。問題がある場合だけ、総合評価の上限を下げる。
- `文字の広さ` は生成条件の補助情報として表示し、総合評価の加点には使わない。
- `S` は、十分な長さと十分な総当たり耐性があり、重大な既知リスクや推測されやすいパターンが検出されない場合に限る。
- `F` は明確に短い、総当たり耐性が低い、blocklist 全体一致、または全体の大半が単純パターンに該当する場合に使う。

### 評価軸

結果行には以下を表示する。

- `長さ`
  - 文字数そのものの評価。
  - NIST/OWASP の 15 文字基準を重視する。
- `総当たり耐性`
  - 文字セットサイズと、ランダム生成された文字数から見積もった entropy bits の評価。
  - `推定エントロピー: xxx bits` はこの軸の補助情報として表示する。
- `文字の広さ`
  - 生成に使える文字セットの広さを補助情報として表示する。
  - 大文字・小文字・数字・記号の混在を必須とはしない。
  - 文字種の強制ではなく、探索空間の広さを説明するための情報とする。
- `既知リスク`
  - よく使われる単語、サービス名、パスワード由来語、ローカルの軽量 blocklist との一致を評価する。
  - オンライン漏洩データベース照合は行わない。
  - 漏洩データベース全体との一致は保証しないため、評価軸名は `漏洩安全性` ではなく `既知リスク` とする。
  - アプリ内の軽量 blocklist とパターン検出に基づく推定リスクとして扱い、問題がある場合だけ警告として表示する。
- `推測されにくさ`
  - 連番、キーボード配列、日付、繰り返し、短いブロック反復など、攻撃者が優先的に試しやすい構造を検出する。
  - 問題がある場合は `推測されやすいパターン` として警告表示する。

`Variety` と `Balance` の英語バッジは廃止する。必要な計算は内部評価に使ってもよいが、ユーザー向け表示には出さない。

### 結果行での表示密度

- 生成結果行では、パスワード文字列の視認性と一覧性を優先する。
- S-F のグレードチップは主評価だけに絞る。
  - `総合`
  - `長さ`
  - `総当たり耐性`
- `総当たり耐性` は表示幅に収まるため、短縮ラベルの `耐性` は使わない。
- `推定エントロピー: xxx bits` は生成結果一覧の上側に補助情報チップとして 1 回だけ表示する。
- `文字の広さ` は `条件: 文字セット数 / カテゴリ数` のような補助情報として、生成結果一覧の上側に 1 回だけ表示する。
- `ハッシュ: shortid` は生成結果一覧の上側に小さく表示し、結果セットの識別に使えるようにする。
- `既知リスク` と `推測されやすいパターン` は、問題がない場合はチップにしない。問題がある場合だけ補助メッセージに出す。
- 詳細な意味は `?` の説明 tips と README で補足する。
- 通常の結果行では、総合評価と主要グレードだけを表示し、各パスワード固有ではない `推定エントロピー` と `条件` は繰り返さない。

### 長いパスワードの省略表示

- 結果一覧では、各パスワードの表示文字列は先頭 100 文字までに省略する。
- コピー、テキスト出力、強度評価には省略前の全文字列を使う。
- 省略表示の注記は各パスワード行には出さない。
- 生成結果一覧の外側、一覧の上側に共通注記として表示する。
- 共通注記は、生成結果に 100 文字を超えるパスワードが含まれる場合だけ表示する。

## グレード基準

### 長さ

- `S`: 24 文字以上
- `A`: 20-23 文字
- `B`: 16-19 文字
- `C`: 15 文字
- `D`: 8-14 文字
- `F`: 7 文字以下

### 総当たり耐性

推定 entropy bits で評価する。

- `S`: 128 bits 以上
- `A`: 100-127.9 bits
- `B`: 80-99.9 bits
- `C`: 60-79.9 bits
- `D`: 40-59.9 bits
- `F`: 40 bits 未満

推定 entropy bits は、ランダムに選ばれる文字数だけを対象にする。固定文字としてユーザーが指定した部分は、攻撃者に知られている前提で entropy に加えない。

### 文字の広さ

生成に使える実効文字セット数と、有効な文字カテゴリ数を補助情報として表示する。

- 表示例: `条件 94字/4種`
- 文字セットが 9 文字以下など極端に狭い場合だけ、補助メッセージで注意を出す。
- S-F グレードとしては表示しない。
- 総合評価の加点には使わない。NIST/OWASP が否定している「文字種を必須にするルール」と混同しない。

### 既知リスク

- NIST の考え方に合わせ、blocklist はパスワード全体または単純派生との照合を中心に扱う。
- 任意の部分文字列に一般語が偶然含まれただけでは、既知リスクを大きく下げない。
- 長いランダム生成結果では、短い一般語の偶発的な出現は原則として減点対象にしない。
- blocklist や一般語の検出は軽量なローカル判定であり、検出がないことは「漏洩済みではない」ことを保証しない。
- S-F グレードとしては表示しない。
- 状態は内部的に以下の警告レベルとして扱う。
  - `なし`: blocklist 全体一致、単純派生、支配的な一般語が検出されない。
  - `注意`: 一般語やサービス由来語が一定割合を占める。
  - `警告`: 弱い語句を leet 変換、前後の少数文字、末尾数字などで単純に変形したもの。
  - `危険`: blocklist 全体一致、または明確に既知の弱いパスワード候補。

### 推測されにくさ

パターン検出を使い、検出数だけではなく、パスワード全体に対するパターンの占有率と重大度を評価する。

長いランダム生成結果では、連番、短いキーボード配列、短い日付らしい数字が偶然含まれることがある。そのため、短い一致がごく一部に出ただけでは減点せず、全体の大きな割合を占める場合や、十分に長い連続パターンだけを減点対象にする。

- 危険パターンが見つからないことは、加点ではなく「減点しない」扱いにする。
- S-F グレードとしては表示しない。
- 状態は内部的に以下の警告レベルとして扱う。
  - `なし`: 減点対象になるほど意味のあるパターンがない。
  - `軽微`: 軽いパターンがあるが、全体に占める割合は小さい。
  - `注意`: パターンが一定割合を占める。
  - `警告`: 連番、キーボード配列、日付、繰り返しなどが全体の大半を占める。
  - `危険`: パスワード全体またはほぼ全体が明確なパターンで構成される。

## 総合評価の決め方

総合評価は、長さと総当たり耐性の組み合わせで基礎評価を決め、既知リスクと推測されやすいパターンで必要に応じて上限を下げる。

基礎評価:

- `S`: 長さ 24 文字以上、かつ 128 bits 以上。
- `A`: 長さ 20 文字以上、かつ 100 bits 以上。
- `B`: 長さ 16 文字以上、かつ 80 bits 以上。
- `C`: 長さ 15 文字以上、かつ 60 bits 以上。
- `D`: 長さ 8 文字以上、かつ 40 bits 以上。
- `F`: 上記未満。

上限制約:

- `既知リスク` が `危険` の場合、総合評価は `F` にする。
- `推測されやすいパターン` が `危険` の場合、総合評価は `F` にする。
- `既知リスク` または `推測されやすいパターン` が `警告` の場合、総合評価は最大 `C` にする。
- `既知リスク` または `推測されやすいパターン` が `注意` の場合、総合評価は最大 `B` にする。
- `推測されやすいパターン` が `軽微` の場合、総合評価は最大 `A` にする。
- `文字の広さ` だけが狭い場合は、総合評価の上限制約には使わない。ただし、補助メッセージで注意を出す。

## 補助メッセージ

補助メッセージは日本語で表示する。

- 補助メッセージは、問題、注意点、改善余地がある場合だけ表示する。
- `S` や `A` で警告がない場合は、無理に肯定文を表示しない。
- `総合評価も確認してください` のような、画面上の別表示を参照させるだけの文言は表示しない。
- `B` や `C` の場合は、単なる警告ではなく、どの設定をどう変えると改善するかを短く表示する。
- 例: `文字数が短めです。15文字以上を推奨します。`
- 例: `15文字は最低目安です。重要な用途では20文字以上を推奨します。`
- 例: `総当たり耐性が低めです。文字数を増やすと改善します。`
- 例: `重要な用途では100 bits以上にすると余裕が出ます。`
- 例: `推測されやすいパターンを含みます: 連続文字列`
- 例: `既知の弱い語句を含みます。`
- 例: `文字セットが狭いため、同じ長さでも候補数が少なめです。`

補助メッセージは最大 2-3 件に絞り、重要度の高い理由から表示する。

## 制約

- 実装は Swift / SwiftUI の標準機能で完結させる。
- 生成処理が UI を固めないよう、評価処理は生成済みの各パスワードに対して軽量に行う。
- 暗号学的に安全な乱数生成そのものは変更しない。
- 判定は目安であり、オンライン漏洩データベース照合や外部通信は行わない。
