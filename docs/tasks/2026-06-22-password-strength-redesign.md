# パスワード強度評価の再設計タスク

## 背景

`既知リスク` と `推測されにくさ` を S-F の加点評価として表示すると、危険シグナルが見つからないだけで強さを保証しているように見える。長さや entropy の上限を混ぜると、評価軸の意味がさらに分かりづらくなる。

生成アプリとしては、長さと総当たり耐性を主評価にし、既知リスクや推測されやすいパターンは問題がある場合だけ総合評価を下げる警告として扱う方が自然。

## タスク

- [x] 強度評価仕様を、主評価・補助情報・警告に整理する。
- [x] 結果行の S-F チップを `総合`、`長さ`、`耐性` に絞る。
- [x] `文字の広さ` を `条件` の補助情報として表示する。
- [x] `既知リスク` と `推測されやすいパターン` を S-F 表示から外し、警告レベルとして扱う。
- [x] 総合評価を、長さと entropy の基礎評価に、既知リスクとパターンの上限制約をかける方式へ変更する。
- [x] 固定文字は entropy に含めないよう補正する。
- [x] 強度評価 tips を、表示ラベル別・基準別の重複表ではなく、画面の読み方として分かりやすく再構成する。
- [x] README の強度表示説明を更新する。
- [x] Xcode build で確認する。
- [x] 実装後に強度評価仕様を再評価し、追加タスクの要否を判断する。

## 完了条件

- `既知リスク` と `推測されにくさ` が、問題なしの場合に S-F の `S` として表示されない。
- 短いパスワードが、危険シグナル未検出だけで強く見えない。
- 長いランダム生成結果が、短い偶発一致だけで不当に低評価にならない。
- 固定先頭文字を使った場合、固定文字ぶんは推定 bits に含まれない。
- tips を読めば、`総合`、`長さ`、`耐性`、`bits`、`条件`、警告メッセージの意味が分かる。

## 実装後レビュー

- `既知リスク` と `推測されやすいパターン` は S-F チップから外れ、問題がある場合だけ警告として表示されるため、危険シグナル未検出が強さの満点に見える問題は解消した。
- 総合評価は `長さ` と `総当たり耐性` の低い方を基礎評価にするため、短い生成結果が既知リスク未検出だけで高評価になることはない。
- 長いランダム生成結果は、短い偶発一致だけでは警告対象にならないため、不当に低評価になりにくい。
- 固定文字は推定 bits から除外し、先頭文字種の制限も先頭 1 文字ぶんだけ狭い文字セットとして見積もるようにした。
- tips は `結果行の読み方`、`グレードの意味`、`警告の扱い` に整理し、同じ項目を複数表で説明する構成をやめた。
- 追加タスクは不要と判断した。大規模辞書、オンライン漏洩照合、厳密な制約付き entropy 計算は、このアプリのローカル生成用途に対して現時点では過剰。
